\section{System Introduction \& Strategic Framework}

\subsection{Industrial Operations Context}
Modern assembly setups require sub-millisecond precision, heavy machinery coordination, and reliable feedback loops. For decades, factories relied entirely on isolated physical logic loops called PLCs (Programmable Logic Controllers) to maintain stability. While highly reliable for fixed local execution, legacy systems lack native, long-range cryptographic capabilities, cloud aggregation mechanics, and flexible data-driven monitoring frameworks.

The recent push to incorporate wireless edge computing options—popularly called Industrial Internet of Things (IIoT)—introduces a critical integration layer. By deploying affordable microcontrollers directly onto manufacturing floor equipment, organizations gain access to immediate parameter scaling, automated environmental metrics, and long-range remote telemetry tracking.

\subsection{The Integration Challenge}
When unshielded wireless architectures interface with mission-critical machinery loops, it introduces significant technical vulnerabilities. Unencrypted operational data blocks transmitted over shared localized frequencies create accessible vectors for network spoofing, signal degradation, and malicious instruction hijacking. 

Furthermore, low-cost sensor nodes operating continuously in extreme factory configurations frequently encounter hardware fatigue. This results in signal decay, thermal calibration drift, and intermittent communication timeouts that can cause automated control systems to trip safety thresholds.

\subsection{Proposed Innovation Loop}
This project solves these limitations by upgrading the standard message-routing interface into an automated security monitor, avoiding expensive modifications to legacy controllers or field equipment. By implementing a local, analytical parsing script directly within the message broker's operating environment, the system monitors device network data and system log traffic continuously.

\section{Problem Statement \& System Engineering Constraints}

\subsection{Formal Problem Definition}
\label{sec:problem_def}
Industrial automated networks lack built-in security, real-time diagnostic awareness, and validation mechanisms at the messaging layer. This leaves systems vulnerable to three critical operational risks:
\begin{enumerate}
    \item \textbf{Malicious Physical Intrusions:} Malicious field implants can spoof system credentials, hijack topics, and issue unsafe override commands to active equipment.
    \item \textbf{Telemetry Hardware Degradation:} Low-cost environmental monitoring sensors degrade quickly under heavy operational wear, causing reporting errors that can lead to unnecessary system shutdowns.
    \item \textbf{Unmanaged Network Latency Jitter:} Processing latency fluctuations and communication timeouts within shared local wireless spaces can delay critical safety instructions, risking mechanical collision or failure.
\end{enumerate}

\subsection{System Constraints Analysis}
To ensure this solution is viable for real-world manufacturing environments, the design must operate within strict physical, electrical, economic, and timing boundaries.

\section{Engineering Design Objectives \& Solution Specifications}

\subsection{Primary Functional Goals}
The design objectives focus on creating an automated monitoring layer that requires no structural modifications to existing production machinery.

\begin{itemize}
    \item \textbf{Dual-Layer Message Processing:} Implement standard message routing concurrently with a local log analysis pipeline to run diagnostics without delaying high-priority control commands.

    \item \textbf{Low-Power Edge Design:} Optimize edge microcontroller firmware to maximize battery life, utilizing deep sleep modes during non-transmission intervals to conserve backup power.

\section{Detailed Methodology \& Subsystem Configurations}

\subsection{Physical Micro-Node Node Layout}
The proof-of-concept environment utilizes four physical nodes to simulate an automated assembly environment.

\subsubsection{Node 1: Variable Motor Actuator Station}
Built on an ESP32 architecture, this unit manages a localized DC motor using an integrated driver circuit. It subscribes directly to the `factory/actuation/motor` data channel, converting incoming control payloads into corresponding pulse-width modulation (PWM) output signals to regulate motor operation.

\subsubsection{Node 2: High-Visibility RGB Alert Array}
This safety interface translates system statuses into immediate visual cues. By monitoring the `factory/alerts/signaling` channel, it changes its light patterns to show normal operation, parameter warnings, or critical system failures.

\subsubsection{Node 3: Dedicated Environmental Telemetry Module}
This node samples real-time environmental metrics using a digital DHT11 sensor. It reads local ambient temperature and relative humidity every two seconds, packages the data into structured JSON blocks, and transmits them over the `factory/telemetry/ambient` topic thread.

\subsubsection{Node 4: Master Control & HMI Interface Deck}
This operational console serves as the primary manual input and monitoring station for the local hardware cluster.

\section{Firmware Design \& Automated Anomaly Processing Engine}

\subsection{Log Telemetry Structure}
The monitoring script parses system logs continuously. Each record tracks the execution time, connection status, originating IP, unique hardware ID, and targeted communication topic.

\subsection{Core Processing Implementation}
The Python routine below reads the active log file, tracks device connections, and scans incoming metrics for unusual deviations or data spikes.

\begin{lstlisting}[language=Python, caption=Real-Time System Log Parsing and Anomaly Detection Loop]
import os
import time
import re

# System log configuration paths
LOG_FILE_PATH = "/var/log/mosquitto/mosquitto.log"
TELEMETRY_CEILING = {"temp": 50.0, "humidity": 90.0}
KNOWN_DEVICES = {"ESP32_MOTOR_01", "ESP32_RGB_02", "ESP32_DHT11_03", "HMI_DECK_04"}

def analyze_log_record(record_string):
    # Check for unauthorized device connection attempts
    if "New client connected" in record_string:
        match = re.search(r'as\s+(\w+)', record_string)
        if match:
            device_id = match.group(1)
            if device_id not in KNOWN_DEVICES:
                print(f"[SECURITY ALERT] Unauthorized Device Detected: {device_id}")
                return "SECURITY_VIOLATION"
                
    # Check for telemetry spikes indicating sensor issues or failure
    if "PUBLISH" in record_string:
        # Example extraction format: temp:value, humid:value
        metric_match = re.search(r't_val=(\d+\.\d+)\|h_val=(\d+\.\d+)', record_string)
        if metric_match:
            temperature = float(metric_match.group(1))
            humidity = float(metric_match.group(2))
            if temperature > TELEMETRY_CEILING["temp"] or humidity > TELEMETRY_CEILING["humidity"]:
                print(f"[METRIC ALERT] Sensor Out-Of-Bounds: Temp={temperature}C, Humid={humidity}%")
                return "TELEMETRY_ANOMALY"
    return "STATUS_NORMAL"

def initiate_monitoring_loop():
    print("Initializing Smart Broker Anomaly Analysis Engine...")
    try:
        log_handle = open(LOG_FILE_PATH, "r")
        log_handle.seek(0, os.SEEK_END)  # Move to the end of the current log
        
        while True:
            new_record = log_handle.readline()
            if not new_record:
                time.sleep(0.1)  # Yield processing time slice
                continue
            
            evaluation_status = analyze_log_record(new_record.strip())
            if evaluation_status != "STATUS_NORMAL":
                # Execute alert logging or isolate compromised node
                pass
    except FileNotFoundError:
        print(f"[CRITICAL ERROR] Target Log Path Invalid: {LOG_FILE_PATH}")

if __name__ == "__main__":
    initiate_monitoring_loop()
\end{lstlisting}

\subsection{Critical Path Analysis & Risk Assessment}
The most critical phase of development lies in the integration of the log analysis loop with the message broker. If parsing routines introduce processing delays, it can disrupt real-time equipment communications. To prevent this, the analysis script runs as an isolated background task, ensuring standard message routing remains completely unhindered.

\subsection{Academic Compliance & KTU Framework Requirements}
This architecture aligns with the technical design criteria established in the \textbf{APJ Abdul Kalam Technological University (KTU)} engineering curriculum.

\subsection{Ethical Engineering Implementation}
The monitoring architecture is designed with high ethical standards regarding data handling and operational safety. All automated analysis remains strictly within the local factory network environment, protecting sensitive production metrics from external exposures. Additionally, the system features manual command overrides, ensuring human operators retain ultimate control over physical equipment behavior at all times.

\subsection{Concluding Design Remarks}
This design specification presents a scalable, cost-effective approach to improving operational security and fault visibility on manufacturing plant floors. Upgrading the messaging broker into an active monitoring hub allows the system to identify equipment degradation and security anomalies early, protecting legacy infrastructure without requiring complex or expensive modifications to existing hardware.
